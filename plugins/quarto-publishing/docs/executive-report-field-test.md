# Executive-academic Quarto field test

## Target and scope

**Decision:** the revised source is mature within the tested source, evidence, render and static-structure boundaries. Full end-to-end saturation is **not reached**: full-page visual/interactive inspection and installed-context discovery remain unverified.

This hardening evaluation ran on 7–8 September 2026 against `quarto-publishing` 0.2.0 with Unreleased working-tree changes, based on repository revision `da65f36d51525ee188b54f175c58904916c6cbfb`. It follows review of the original report-writing interaction and an earlier three-trial evaluation. The original private analytical work was read-only; field trials used synthetic evidence in isolated temporary directories.

The target was the existing authoring, report-design, format-configuration and render-troubleshooting skills. No separate report skill, universal terminology blacklist or fixed executive report outline was introduced. Local punctuation, terminology and labeling preferences remain project constraints. At evaluation close, the source version remained 0.2.0 and no commit, tag, installation, marketplace update or publication had been performed. The unrelated root release-process edit was preserved.

## Evaluation design and model attribution

The hardening campaign contains 19 independent artifact-generation trials: two matched baseline runs and five development/confirmation waves. An additional matched run is a model comparison, not a distinct scenario for wave qualification. All agents received fresh contexts, explicit model/effort assignments, an immutable plugin snapshot, isolated workspace and a user-like request. User requests contained **14–26 words**. Environment instructions separately constrained write paths and live effects; they contained no expected answer, failure diagnosis or scoring rubric. Fixtures supplied source evidence and ordinary project constraints.

Example nominal request: “Usa el plugin de Quarto para hacer un QMD ejecutivo-académico sobre este análisis, con imágenes y explicaciones para entender qué funciona y qué falta. Salida HTML.”

Explicit assignments were **Sol high**, **Sol medium** and **Luna max**. The matched municipal-report runs held the prompt and evidence constant across models and recorded the source snapshot. This supports case-level diagnosis, not a model ranking or causal estimate of the skill's effect. There was no randomized no-skill control, and system/runtime knowledge could also contribute. Supplying the plugin path tests use of its source instructions, not autonomous discovery from the installed catalog.

Failures were not automatically attributed to Luna. Sol high produced escaped custom cards and incompatible subtitle colors in the preceding evaluation; Sol medium later misqualified totals with unknown classification. Luna introduced an incorrect plan requirement and an observation-unit substitution. Fresh retests address missing general controls, while a self-corrected working-directory deviation remains a model/tool-execution finding.

The HTML checker is a read-only standard-library helper. It checks duplicate IDs, same-document anchors and supported local image/script/stylesheet paths. HTML in code is an advisory, not an automatic failure. Its bounded JSON explicitly excludes remote/root-relative/data URLs, dynamic behavior, CSS-contained resources, visual quality and interaction. Exit zero means no definite errors in that limited scope, not publication readiness.

## Evaluator and harness findings

The parent withdrew an overstrict methodological classification. General explanation beyond a short handoff is not automatically an invented study fact. Independent-cohort replication and external-criterion relationships are legitimate explanatory emphases in methodological sources; neither identifies this synthetic project's unprovided procedure. The material issue retained is false attribution of a requirement or executed design. See the [author manuscript, p. 11](https://escholarship.org/content/qt7nc4f935/qt7nc4f935_noSplash_5ef66421997e5cbbaff9b9ddaba02838.pdf) and the [LCVAR external-validation section](https://link.springer.com/article/10.3758/s13428-025-02909-7).

One Luna trial briefly created a new QMD at the repository root through a relative tool path and then removed it. The parent confirmed no residual file. Later environment briefs explicitly stated the inherited tool directory and absolute write paths. The final teaching trial also received a completion/source-delivery reminder without expected answers; that follow-up is retained in the record. This correction did not disclose the expected report answer. All five revised snapshot hash inventories remained unchanged, and final skill/manifest contents match Revised-5.

Cosmetic observations include overprioritized configuration recommendations, repeated automatic figure-type labels, a mechanically explicit narrative sequence, and unnecessary specificity in a proposed technical column label. They do not justify universal prohibitions or a rigid template. The rewrite trial reported a no-execution HTML preview and left support libraries in its temporary workspace despite saying no additional artifacts remained; directory-cleanliness claims were not accepted as evidence. The requested delivery remained the QMD.

## Validation and saturation decision

Native validation passed for the plugin and all six skills. The ten HTML-checker regression tests and `git diff --check` passed. The final field-test record validator reported zero errors and zero warnings. Eleven trial reports were independently rendered to HTML, plus a separate repair regression for the original escaped cards. Applicable original and independently rendered HTML artifacts received static structural checks. Source/evidence review included units, exact values, arithmetic, weights, decision requirements, missingness, preserved approved content, code visibility and authorization boundaries.

Explicit no-render requests were checked through source comparison and `quarto inspect`, without claiming output validation. A request to deliver only the QMD was distinguished from an explicit prohibition on temporary preview rendering. Selected generated PNG figures were inspected directly; this is not a full-page visual check.

The default saturation rule requires two consecutive waves after the last material fix, at least three nonduplicative scenarios per wave, no new/recurrent material findings, independent artifact checks and passing native regressions. H4 and H5 each completed three nonduplicative scenarios after the final material fix, with no new or recurrent material findings in independently checked source/evidence and applicable render/static-structure surfaces: **two consecutive clean waves within the available checks**. Full-verification clean waves remain zero. The campaign records these scopes separately. Browser and installed-discovery gaps prevent an unqualified saturation claim, regardless of the JSON validator's structural acceptance.
